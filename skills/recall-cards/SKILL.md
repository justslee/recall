# Cards

For questions while reading, follow ../recall-source/references/active-reading.md. Reuse suitable concept cards and separately check for meaningful missing math/coding exercises. Return verified links only after import; generated exercises are not evidence of mastery.

Read ../recall-source/references/quality.md. Search existing card IDs, titles and answers before authoring. For a full document/deck request, inventory every section/card and record existing, new or excluded objectives with reasons. Author the answer first. Record math and coding suitability separately; reuse an existing specialist exercise if it tests the same objective. Use recall-visuals, recall-math and recall-code only where they help. Validate using the CLI, render in an isolated profile and verify import idempotence before the authorized live import. Report exact counts and gaps. Existing-content conflicts require reviewed revisions, not duplicate IDs.

When resolving queued learning, follow ../recall-source/references/inbox.md. Submit validated bundles through the inbox so the app can import while open. Keep failed checks visible; do not mark pending objectives ready.

For interactive visuals, check the installed `RecallVisual` toolkit and read the versioned widget contract through recall-visuals. Use a single state model for inputs, marks and interpretation. Keep actual scenario/screenshot acceptance separate from syntax/import validation; unavailable visual QA leaves a draft. For an authorized visual upgrade, use the widget-only expected-content-hash revision workflow in quality.md under the existing card ID, preserving prose, permissions and review history. Show requested benchmark visuals before proposing wider migration.


## Quiet preparation and verification

Reuse existing ready objectives immediately; prepare only genuine gaps. Routine card QA must never open, focus, flip through or restart the reader’s Recall window. Follow [invisible-verification.md](../recall-source/references/invisible-verification.md) for hidden actual-renderer checks, exact-content caching and the separate editorial/math/code requirements. Keep pending checks visible; never turn a generated report into execution trust.
