## October 3 · Device-local OpenAI key

Device-local OpenAI connection (October 3, 2026): Recall's API-key status, save, dictation and evaluation paths no longer use Electron `safeStorage` or macOS Keychain. Each profile stores its own key in `credentials/openai.key`, with owner-only `0600` file and `0700` folder permissions, without separate encryption. Software running as the same OS account can read it. Saved keys remain main-process-only and outside Recall exports/profile backups; docs and Settings state the tradeoff. Legacy `openai.enc` files are detected without reading/decrypting them and preserved until successful local re-entry or explicit removal. A legacy cleanup failure reports the local save accurately. Linked, hard-linked, foreign-owned and invalid credential files fail safely. Backup destinations must be empty so unrelated files cannot enter a profile backup.

Verified: all 102 tests, production build and packaging, source/history and actual-package privacy audits, source and packaged synthetic voice flows, and packaged Speak flows with mocked provider responses. The voice checks force Keychain API methods to throw and verify legacy re-entry, saved-key restart usability, secret-free status and unchanged study state. The installed app was archived privately, updated and opened to the one-time re-entry Settings screen; all seven library tables and the existing encrypted credential bytes matched the baseline, with SQLite integrity verified. No real key was decrypted or transmitted. The user must re-enter their key once to enable the new local connection. Earlier encrypted-storage notes below describe previous builds.
